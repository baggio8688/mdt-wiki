# 工厂车间AI治理 - 白话版

> **原文：** *Building An AI Governance Framework for the Factory Floor*
> **来源：** Manufacturing Leadership Council（2026-05-21）


## 一、大家都在用AI，但心里没底

现在做制造的，AI已经不是什么新鲜东西了。数据摆在那：**87%的制造企业**都在用生成式AI——ChatGPT也好，Azure AI也好，Microsoft Copilot也好，总归是有人在用。

真正的问题是——**用了，然后呢？**

调查里有个数字更值得注意：28%的企业在搞AI项目时已经吃过亏了。其中1/4的人明确说——吃亏就吃在 **没治理** 上。模型上线了，没人说得清谁该对它的输出负责。出问题再补救，机器都停过一轮了。

### 制造业AI的风险，跟互联网公司不一样

银行搞AI，模型判断错了，最多是个坏账。车间里AI搞错了，后果是物理的：

- 生产线AI判断失误，设备直接撞停甚至出安全事故
- AI跟PLC、SCADA绑在一起，安全边界在哪谁都说不清楚
- 模型一抽风，整批产品的质量就漂移了

这不是IT部门该管的事——但只靠车间主任也管不了。


## 二、搞AI治理，抓住这五件事就够了

MLC（制造业领导力委员会）给出的框架，其实不复杂。五个支柱，一条条说人话：

### 1. 先把数据管起来

制造业的问题永远出在同一个地方：**数据太乱**。传感器来的、工控机来的、老师傅手工填Excel的，格式各异、标准不同。

怎么解决？
- 建一个**数据质量看板**，一眼能看到车间数据源哪些是干净的、哪些是脏的
- 每个数据源都写清楚：从哪来、谁负责、什么格式

听起来麻烦。但数据不干净，AI就是垃圾进垃圾出，谁用谁吃亏。

### 2. 成立AI监督委员会

别被名字吓到。说白了就是**拉一桌人定期碰个头**。

谁来：运营的人、IT的人、数据的人、安全的人、能拍板的高管。

干什么：
- 新上线一个AI用例，先过会审议
- 定期问一个问题：**这个AI到底帮我们省了多少钱？**——停机时间降了多少？良率升了几个点？说不出来就重新评估。

### 3. 管好外来的AI工具

大多数制造商不会自己写AI，都是买别人的。

买之前问供应商三件事：
1. 这个工具能看我的哪些数据？
2. 我的数据拿去了怎么用的？
3. 出了偏差你们管不管？准确性如何？能不能解释？

千万别签完合同再问。

### 4. 每个AI用例上线前先做风险评估

每上一个AI，都要回答几个硬问题：
- 这个AI出错了会怎样？
- 最坏的后果是什么？
- 有没有人可以兜底（人工判断兜底）？

这不是走流程，是真要写在纸上让人签字。

### 5. 对齐现有的合规要求

AI不是法外之地。它得跟现有的法规对上：
- 数据保护和隐私（比如《个人信息保护法》）
- 网络安全（等保2.0）
- 产品质量责任
- 内控审计要求


## 三、你们厂现在到哪一步了？

| 阶段 | 什么表现 |
|------|---------|
| 1. 野路子 | 谁想用谁用，没人管、没人监督 |
| 2. 救火队 | 出事了才管，每次都是事后补救 |
| 3. 上轨道 | 五件事基本建起来了，谁负责什么清晰了 |
| 4. 能量化 | 每个AI能算清楚账，持续监控 |
| 5. 成优势 | 治理本身变成竞争力，不怕上AI就怕上得慢 |

大部分工厂现在在 **1到2之间**。

## 四、一句话总结

> AI治理不是什么高大上的东西。它就是：**想清楚再上，上了有人管，管了能算账。**

先把数据整干净，再拉几个人定期开会，把每个AI用例的风险和责任说清楚。做到这三点，就已经领先大部分同行了。
